## 3. 文件管理核心链路

### 3.1 第二轮：单分片上传 → 秒传 → 下载（07:30–07:33）

源文件 `.local-test-data/pan123-cli-lockcheck-20261014-0730.bin`，32,789 字节，MD5 `cc8b3074c99d71c04b432c475563824a`。

| 步骤 | 命令（去敏） | 结果 |
| --- | --- | --- |
| 鉴权 | `pan123 … auth ensure` | `cached=true usable=true`，`expires_at=2027-01-11T22:58:32+00:00` |
| 上传 | `pan123 … file upload --file <源文件> --parent-id 33175809` | `file_id=33175930`，`size=32789`，`md5` 与源文件一致，`reused=false`，`verified=true` |
| 秒传 | 同字节内容换名再次上传 | `file_id=33602404`，`reused=true`，`verified=true` |
| 下载 | `pan123 … file download --file-id 33175930 --output <本地副本> --yes` | `size=32789`，`md5` 一致，`verified=true`；本地副本字节与源文件相同 |

高层的 `file upload` 依次走到 `POST /upload/v2/file/create`、`POST /upload/v2/file/slice`、`POST /upload/v2/file/upload_complete`，成功后再用 `GET /api/v1/file/detail` 读回核对 `type`/`size`/`etag`/`trashed`/`status`；`verified=true` 即读回通过。下载使用 `GET /api/v1/file/download_info` 取 CDN 地址，校验字节数与 MD5 后才发布正式文件。

### 3.2 第二轮：底层 upload-api 会话协议（07:35）

| 步骤 | 命令（去敏） | 结果 |
| --- | --- | --- |
| 创建 | `file upload-api v2 create --request-file <对象{parentFileID,filename,etag,size}>` | `reused=false`，`slice_size=16777216`，写出受保护的 `session_file` |
| 分片 | `file upload-api v2 slice --session-file <会话> --slice-no 1 --slice <分片>` | `uploaded=true`，`size=20009`，`md5=a0c69a9a616ea68daa72b45e7d0cf140` 与本片字节一致 |
| 重复分片 | 再次提交同一个 `--slice-no 1` | 退出码 2，`INVALID_INPUT`“That slice is already recorded; unverified replay is not supported.”，未上传任何字节 |
| 完毕 | `file upload-api v2 complete --session-file <会话> --wait` | `completed=true`，`file_id=33573267`，`verified=true` |

重复分片被拒绝依赖“同一会话的读-改-写串行化”：分片动作在会话锁内重新读取会话，因此并发或重放请求不会把同一片记录两次，也不会覆盖另一进程已记录的分片。该行为由 `tests/test_upload.py` 的并发用例覆盖，本轮在真实会话上再次确认。

## 4. 环境相关观察与处理

| 观察 | 处理 |
| --- | --- |
| 直接上传时报 `INVALID_ARGUMENT`“传输地址指向非公网网络”（退出码 2）：本机代理使用 Fake-IP DNS，官方返回的上传域名解析到 `198.18.0.0/15` | 显式加 `--allow-fake-ip` 后成功；默认仍要求公网地址并保持主机名 TLS 校验。错误 `details` 中带回 `session_file`，便于不重放的前提下人工续传 |
| `file download --overwrite` 在非交互环境被拒绝：`INVALID_ARGUMENT`“此变更命令在脚本中需要 --yes”（退出码 2） | 这是设计行为；脚本中显式传 `--yes` 后校验并发布 |

被 Fake-IP 拦截的那次上传在 `.local-test-cache` 留下了 `status=created`、`parts=0` 的会话文件；CLI 不自动重放未确定结果的上传，这是预期状态。

以下能力已实现并通过离线契约测试，但**没有**真实账户证据，不能按“真实可用”对外承诺：
