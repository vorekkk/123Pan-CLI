# 发布到 PyPI

目标是让使用者只输入一条命令：

```bash
uv tool install pan123-cli
# 或
pipx install pan123-cli
```

发布使用 **PyPI Trusted Publishing（OIDC）**，仓库里不保存任何 PyPI token。工作流文件是 [.github/workflows/release.yml](../.github/workflows/release.yml)。

## 1. 发布前的一次性配置

1. 注册/登录 [PyPI](https://pypi.org/)（已启用两步验证）。
2. 打开 [Publishing → Add a pending publisher](https://pypi.org/manage/account/publishing/)，按下面填写：

   | 字段 | 值 |
   | --- | --- |
   | PyPI Project Name | `pan123-cli`（截至 2026-10-14 未被占用，已核验） |
   | Owner | `vorekkk` |
   | Repository name | `123Pan-CLI` |
   | Workflow name | `release.yml` |
   | Environment name | `pypi` |

3. 首次成功发布后会出现同名项目；之后同一配置继续生效，不需要再创建 token。

## 2. 每次发布的步骤

```bash
# 1. 改版本号（唯一来源是 pyproject.toml 的 version）
# 2. 本地完整校验
python -m pytest -q
python -m ruff check src tests scripts
python -m ruff format --check src tests
python -m mypy src/pan123_cli
python -m build
python scripts/check_wheel.py
python scripts/check_release.py --tag v0.1.0

# 3. 提交并打 tag（tag 必须等于 v<version>）
git commit -am "chore: release 0.1.0"
git push origin main
git tag v0.1.0
git push origin v0.1.0
```

推送 tag 后 `Release` 工作流会依次执行：测试与静态检查 → 构建 wheel / sdist → `scripts/check_wheel.py` 干净环境安装验证 → `scripts/check_release.py` 校验 tag、元数据与产物内容 → 通过 OIDC 上传到 PyPI。任何一步失败都不会上传。

## 3. 只验证不发布（dry run）

```bash
gh workflow run release.yml --ref main -f dry_run=true
gh run watch
```

dry run 会完整走构建与校验并上传 artifacts，但跳过 `publish` 任务；用它可以在没有 PyPI 配置时确认流水线健康。

## 4. 校验脚本覆盖什么

| 脚本 | 检查 |
| --- | --- |
| `scripts/check_wheel.py` | 干净虚拟环境安装 wheel，运行 `pan123 --version`、`pan123 file upload --help`、`python -m pan123_cli --help`；wheel 不含 tests / docs / `.env*` |
| `scripts/check_release.py` | tag 与 `pyproject.toml` 的 version 一致；wheel 是 `py3-none-any`、包含全部模块、控制台脚本、`.dist-info/licenses/LICENSE`；必需元数据字段（含 `License-Expression`、`Project-URL`、`Classifier`）齐全；README 长描述非空；sdist 含 `LICENSE`、`README.md`、`pyproject.toml` 与源码，且不含 `.env` |

CI（`.github/workflows/ci.yml`）在每次推送时也会运行 `check_release.py`，所以元数据回归会在合并前暴露。

## 5. 版本与回滚规则

- PyPI 同版本号只能上传一次：改代码后必须递增 `version`（例如 `0.1.1`），不要复用已发布的版本。
- 发布错误时用 PyPI 的 *Yank* 标记该版本，再发一个新版本；不要尝试覆盖。
- tag 与 version 必须一致，`check_release.py --tag` 会在发布前强制这一点。
- `constraints-*.txt` 只记录本机验证过的精确依赖版本；发布元数据仍使用 `pyproject.toml` 中的范围约束。

## 6. 发布完成后的检查

```bash
uv tool install pan123-cli        # 或 pipx install pan123-cli
pan123 --version
```

同时确认 PyPI 项目页面的元数据（描述、许可、主页、Documentation、Issues）正常渲染，并在 README 中把“安装”一节改成不带 `git+` 的命令。
