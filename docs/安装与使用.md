# 安装与使用

此工具直接调用 123 云盘官方 OpenAPI。运行需要 Python 3.12 或更高版本以及官方开发者凭据；第三方限定接口使用单独 OAuth 授权。完整参数以 `pan123 <命令> --help` 和[完整命令参考](./CLI完整命令参考.md)为准。

## 首次配置与 AI Skill

安装完成后运行 `pan123 setup`，输入 Client ID 与隐藏的 Secret，验证成功后保存到平台用户配置目录的私有 `credentials.json`。首次交互业务命令也会自动引导。现有环境变量和显式配置方式仍优先；帮助、版本、JSON、非交互任务不会提示。`auth clear`只清 token 缓存。

Skill 自动检测 Codex、Claude Code、Cursor，支持多选。独立安装：`npm i -g pan123-cli-skill`；指定安装：`npx pan123-cli-skill install --agent cursor --scope project`。npm 包不包含 CLI 运行时。使用 `pan123 skill install|status|uninstall`管理，`--dest`为完整目录，`--force`先备份再处理冲突。

详见 [配置、优先级、目录及安装规则](../skills/pan123-cli/references/configuration.md)。

## 平台范围

| 系统 | 目标架构 | 终端 | 安装方式 |
| --- | --- | --- | --- |
| macOS | Apple Silicon ARM64、Intel x86_64 | zsh / bash | Python 虚拟环境、pipx、wheel |
| Linux | x86_64、ARM64 | bash / zsh | Python 虚拟环境、pipx、wheel |
| Windows | x86_64、ARM64 | PowerShell、cmd | Python 虚拟环境、pipx、wheel |

源码和 wheel 不包含平台专属业务代码。Python 及依赖需要与目标架构兼容；Linux ARM64 和 Windows ARM64 的原生验证采用可选 CI，实际验证结果见实施记录。此版本交付 Python 包，不包含无需 Python 的独立 exe / Mach-O / ELF 程序。32 位系统、Android、iOS 和其他 Unix 变体不在验收矩阵中。

## 一行命令安装（推荐）

仓库公开，`uv`（或 `pipx`）会为工具建立独立环境并把可执行文件放进 PATH，不需要克隆，也不需要手动创建虚拟环境。发布到 PyPI 之后：

```bash
uv tool install pan123-cli
pan123 --help
```

在 PyPI 首发之前，用仓库地址代替包名：

```bash
uv tool install git+https://github.com/vorekkk/123Pan-CLI.git
pan123 --help
```

```bash
pipx install git+https://github.com/vorekkk/123Pan-CLI.git
pan123 --help
```

`uv` / `pipx` 自带 Python 3.12+ 解释器要求；工具本身仍需要 Python 运行时，因为当前交付的是 Python 包。卸载使用 `uv tool uninstall pan123-cli` 或 `pipx uninstall pan123-cli`。发布细节与 Trusted Publishing 配置见[发布到 PyPI](./发布.md)。

## macOS / Linux 源码安装

以下操作在终端运行；`python3` 必须为 3.12+。

```bash
git clone https://github.com/vorekkk/123Pan-CLI.git
cd 123Pan-CLI
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/pan123 --version
.venv/bin/pan123 --help
```

无需激活虚拟环境即可使用 `.venv/bin/pan123`。激活后可直接用 `pan123`：

```bash
source .venv/bin/activate
pan123 file list --help
```

## Windows PowerShell 源码安装

若已安装多个 Python 版本，请确保所选解释器为 3.12+。不依赖 PowerShell 的激活脚本执行策略，直接使用虚拟环境程序：

```powershell
git clone https://github.com/vorekkk/123Pan-CLI.git
Set-Location 123Pan-CLI
py -3 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install .
& .\.venv\Scripts\pan123.exe --version
& .\.venv\Scripts\pan123.exe --help
```

## Windows cmd 源码安装

```bat
git clone https://github.com/vorekkk/123Pan-CLI.git
cd 123Pan-CLI
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install .
.venv\Scripts\pan123.exe --help
```

文件路径带空格时用双引号；PowerShell 可用单引号。UTF-8 JSON 文件由 CLI 读取，cmd 显示中文异常时可先执行 `chcp 65001`。

## 配置开发者凭据

复制工程 `.env.example` 为 `.env` 并在本机编辑真实的 `PAN123_CLIENT_ID` 与 `PAN123_CLIENT_SECRET`。示例空值不是有效凭据。`.env` 已由 Git 忽略；CLI 仅在明确指定 `--env-file` 时读取它，不自动搜索当前目录。

POSIX：

```bash
cp .env.example .env
.venv/bin/pan123 --env-file .env auth ensure
.venv/bin/pan123 --env-file .env file list --parent-id 0
```

PowerShell：

```powershell
Copy-Item .env.example .env
& .\.venv\Scripts\pan123.exe --env-file .env auth ensure
& .\.venv\Scripts\pan123.exe --env-file .env file list --parent-id 0
```

开发者凭据同时兼容现有 `CLIENT_ID` / `CLIENT_SECRET`。同一配置来源中 PAN123 名称优先；明确的空值不会回退到别名。

编辑 `.env` 之后再执行认证。也可以使用进程环境变量；进程环境优先于 env-file。密钥不支持作为直接命令行值传入，认证命令可用 `--client-secret-stdin` 读取标准输入。

## Fake-IP 代理网络

默认拒绝传输域名的非公开 DNS 地址，并将解析结果绑定到连接。若本机代理的 DNS 使用 198.18.0.0/15，可显式启用 `--allow-fake-ip`（所有命令通用）或 `PAN123_ALLOW_FAKE_IP=true`。该选项仍保持官方域名 Host / SNI 和 TLS 证书验证，URL 中的私网 IP 仍拒绝。

```bash
pan123 --env-file .env --allow-fake-ip file upload --file ./example.txt --parent-id 123456
```

## 常用命令

以下假设已激活工程虚拟环境。ID 使用自己的列表结果替换；示例数字不是实际文件。权限、文件限制和下载流量以账号及官方 API 返回为准。

```bash
pan123 --env-file .env auth status
pan123 --env-file .env user info --json
pan123 --env-file .env file list --parent-id 0 --all --json
pan123 --env-file .env file info --file-id 123456 --json
pan123 --env-file .env file upload --file './报告.pdf' --parent-id 123456
pan123 --env-file .env file download --file-id 123456 --output './报告副本.pdf'
pan123 --env-file .env file download-url --file-id 123456 --json
```

`list`、`upload`、`download` 也可直接作为根命令使用。普通文件 ID 为整数；图床 ID 为字符串且根目录为空字符串，不能把普通文件 ID 规则套到图床命令。

默认下载不覆盖同名目标；明确替换时使用 `--overwrite --yes`。校验失败或中断留下 `.part`，命令返回非零退出码并给出实际临时路径。上传前计算 MD5，完成后查询详情校验；分片进度达到 100% 不等于远程合并已经完成。

## 全部业务域

```bash
pan123 file --help
pan123 share --help
pan123 offline --help
pan123 directlink --help
pan123 image --help
pan123 transcode --help
pan123 oauth --help
```

多字段和批量请求使用 UTF-8 JSON 文件及 `--request-file`。同一请求字段的标量选项与请求文件互斥，固定业务类型不允许改写。变更命令在非交互脚本中需要 `--yes`，帮助页面会列出参数。

PowerShell / cmd 中无需激活时，把上述 `pan123` 换成 `.\.venv\Scripts\pan123.exe`。管道脚本使用 `--json`，stdout 只有一个结果 JSON；进度和诊断在 stderr。不要将 token、提取码或带签名链接的完整输出写入公开日志。

## OAuth 授权

OAuth 需要平台批准的第三方应用，不使用 developer client ID / secret 替代。配置 `PAN123_OAUTH_CLIENT_ID`、`PAN123_OAUTH_CLIENT_SECRET`、`PAN123_OAUTH_REDIRECT_URI` 后执行：

```bash
pan123 --env-file .env oauth authorize-url
pan123 --env-file .env oauth exchange --state received-state --code-stdin
pan123 --env-file .env --auth-mode oauth auth status
pan123 --env-file .env --auth-mode oauth transcode list --help
```

authorize-url 输出官方浏览器链接；回调收到的 state 必须匹配本机待授权记录。exchange 从 stdin 读取回调 code 并保存令牌，仅输出元数据。refresh token 单次有效；刷新结果未知时不能盲目重发，要重新授权。

## wheel / pipx 安装和升级

构建好的 wheel 为 `dist/pan123_cli-0.1.0-py3-none-any.whl`。`py3-none-any` 只说明本包没有平台二进制扩展，依赖仍须适配操作系统和 Python 版本。

```bash
python -m pip install ./dist/pan123_cli-0.1.0-py3-none-any.whl
pan123 --version
```

已有 pipx 时，可在工程根目录执行 `pipx install .`，升级同一路径安装用 `pipx reinstall pan123-cli`。未向公共 PyPI 发布，因此不要执行没有指定来源的 `pip install pan123-cli` 来代替本仓库构建产物。

虚拟环境安装升级用 `python -m pip install --upgrade .`；卸载用 `python -m pip uninstall pan123-cli`。`auth clear` 只清理本机缓存，不撤销远程凭据。卸载包也不会自动删除用户下载或历史 `.part`。

## 开发和验证

```bash
python -m pip install -e '.[dev]'
python -m pytest -q
python -m ruff check src tests
python -m ruff format --check src tests
python -m mypy src/pan123_cli
python -m build
python scripts/check_wheel.py
```

GitHub Actions 自动验证 Linux x86_64、Windows x86_64、macOS ARM64 与 Intel 的 Python 3.12/3.13/3.14；workflow_dispatch 的 arm 选项单独运行 Linux / Windows ARM64。runner 名称按 [GitHub 官方 runner 说明](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)配置，运行结果以实际 Actions 状态为准。

测试使用模拟 HTTP Transport，不读取真实开发者凭据。真实账户联调另行记录控制请求、文件大小与哈希，只操作用户指定的隔离测试资源；带权限或权益的接口未获相应账号资格时，不能以模拟测试宣称真实使用已通过。
